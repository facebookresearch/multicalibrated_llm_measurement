**Why this exists.** Both PA referees pushed on the same gap: the paper contrasts
itself against the ReadMe family (Hopkins & King 2010; Jerzak, King & Strezhnev

does *not* test ReadMe. This memo runs an actual ReadMe estimator on the CAP
corpora, on the **same calibration split and the same five shift scenarios** as
the main analysis, so the numbers drop into SI Table S2.

## What was run (and a fidelity caveat — read this first)

We implemented **classic ReadMe (Hopkins & King 2010)** directly in Python: each
document is summarized by binary word-presence features; for many random feature
subsets we solve the identity `P(S) = P(S|D=1)·π + P(S|D=0)·(1−π)` for the
positive-class proportion `π` (closed-form per subset, two classes), estimating
`P(S|D)` on the labeled calibration set and `P(S)` on the unlabeled target, and
average over subsets. The method is classifier-free.

We did **not** run the official IQSS `readme` (ReadMe2) package. It builds
multilingual word-vector document summaries on a Keras/TensorFlow backend; it is
not installed here and is fragile to build for a four-language corpus. The
important point for interpretation: **ReadMe2 refines the *feature summary*, not
the estimator's assumption.** Both ReadMe and ReadMe2 recover `π` under the
*label-shift* assumption that `P(text-features | class)` is stable between the
labeled and target sets. Our question is whether that assumption survives
*covariate* shift (`P(X)` changes, `P(Y|X)` stable) — and classic ReadMe is the
cleanest, fully-specified test of it. See the caveats section for what ReadMe2
would and would not change.

## Headline result

ReadMe is essentially unbiased **only at baseline** (no shift) and is both
**biased** and **wildly unstable** under every shift we tried. MCGrad stays
within ~2pp with low variance throughout.

### Bias by scenario (percentage points; estimate − true)

| Scenario | Region | True | CC | RG | IPW | Iso | MC (bin) | MC (scores) | SLD | **ReadMe** |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| Baseline (balanced test) | within | 7.9% | +2.2 | +0.5 | +0.1 | +0.1 | +0.1 | +0.2 | +7.4 | **+0.8** |
| Country shift (overweight Belgium) | within | 8.4% | +3.3 | +1.7 | +0.1 | +0.9 | +0.4 | +0.4 | +9.5 | **+67.6** |
| Doc-type shift (overweight bills) | within | 6.3% | +1.6 | −0.3 | +0.1 | +0.0 | −0.0 | +0.1 | +4.9 | **+7.1** |
| Spain media (OOD doc type) | OOD | 19.5% | +3.6 | +3.1 | −12.2 | −2.5 | −1.9 | −4.5 | +21.6 | **+4.5** |
| Belgium TV (OOD doc type) | OOD | 11.1% | +4.8 | +3.7 | −4.5 | +2.6 | +0.7 | +1.6 | +13.7 | **+13.5** |

The +0.8pp at baseline is the validity check: with no shift, the implementation
recovers the true prevalence, as ReadMe should.

### Instability (Monte-Carlo std across feature subsets)

ReadMe's per-run standard deviation is enormous everywhere except, marginally, at
baseline: **11.0** (baseline), **40.9** (country), **32.0** (doc-type),
**41.7** (Spain media), **42.0** (Belgium TV) pp. Even where ReadMe's *mean*
bias is moderate (e.g. Spain media, +4.5pp), a single ReadMe estimate is
near-useless: the feature-subset estimates swing by ±40pp. This instability is
itself a known motivation for ReadMe2's matched-subspace selection.

---

## Mechanism: feature density tracks the bias

ReadMe's binary word-presence summary is sensitive to how many features a
document activates, which scales with document length. The bias tracks the
mismatch between target and calibration feature density almost perfectly:

| Set | Mean active features/doc | Median text length |
|---|---:|---:|
| **Calibration** | 35.7 | 162 |
| Baseline (balanced test) | 35.5 | 160 |
| Country shift (Belgium) | 72.1 | 759 |
| Doc-type shift (bills) | 23.3 | 143 |
| Spain media (OOD) | 4.5 | 69 |
| Belgium TV (OOD) | 14.1 | 143 |

Baseline density (35.5) matches calibration (35.7) → near-zero bias. The
country-shift target is dominated by long Belgian newspaper documents whose
density (72.1) is **double** the calibration set → the +67.6pp catastrophe. The
OOD targets are short, sparse snippets (4.5, 14.1) → bias in the other regime.
This is covariate shift — the document-composition part of `P(X)` — breaking the
stable-`P(S|D)` assumption.

## Robustness to the subset-size hyperparameter

The qualitative story holds across ReadMe's main tuning knob (features per
subset). Bias (pp):

| n_feat | Baseline | Country | Doc-type | Spain media | Belgium TV |
|---:|---:|---:|---:|---:|---:|
| 8 | 4.5 | 57.5 | 15.7 | 10.5 | 19.3 |
| 12 | 2.6 | 61.7 | 8.4 | 9.3 | 17.5 |
| 15 | 3.7 | 63.9 | 10.6 | 7.4 | 14.8 |
| 20 | 1.6 | 71.6 | 3.7 | 3.3 | 15.0 |
| 25 | 0.9 | 76.5 | 1.0 | 0.4 | 14.0 |

Baseline is always small; the country-shift catastrophe is always +57 to +77pp;
Belgium TV is always +14 to +19pp. Larger subsets reduce some within-cal bias but
worsen the country-shift failure — there is no setting that rescues ReadMe under
shift.

## What story do the results tell?

1. **The label-shift family does not transport — now demonstrated directly, not
   by SLD proxy.** ReadMe is the canonical PS quantifier the referees named, and
   it fails the same way SLD does: fine at baseline, biased and unstable under
   covariate shift. This closes the "you never actually tested ReadMe" gap.
2. **MCGrad's advantage is sharp on this axis.** Against ReadMe's +0.8 → +67.6pp
   swing and ±40pp run-to-run noise, MCGrad's ≤0.9pp within-support / ≤1.9pp OOD
   (binary labels) is a clean contrast a methods reader will find persuasive.
3. **The failure is interpretable, not a black box.** The density diagnostic
   shows exactly why ReadMe breaks (within-class feature distribution shifts with
   document composition), which reinforces the paper's theoretical argument
   rather than just adding another losing baseline.
4. **A nuance worth owning:** ReadMe is *not* uniformly worst. On Spain media it
   beats IPW and MC-scores on mean bias (+4.5 vs −12.2, −4.5) — but its ±42pp
   instability makes that mean meaningless. The honest framing is
   "biased *and* unusable-variance under shift," not "always the largest bias."

## Official IQSS `readme` package — confirmation run (added)

The official `readme` package (Jerzak/King/Strezhnev; `iqss-research/readme-software`)
**installs and loads** in a repo-local R library (`cap_analysis/.rlibs`), and the
TensorFlow backend it needs for ReadMe2 is now importable. Its bundled classic
estimator, `readme0()`, was run on the **identical** calibration and target
documents exported from the Python pipeline (`readme_export_*.csv`). Bias (pp),
two settings (features=15):

| Scenario | True | `readme0` nboot=50, vocab 1500 | `readme0` nboot=200, vocab 2500 | (our Python ReadMe) |
|---|---:|---:|---:|---:|
| Baseline | 7.9% | +7.4 | +5.3 | +0.8 |
| Country shift | 8.4% | +45.2 | +60.1 | +67.6 |
| Doc-type shift | 6.3% | −4.8 | −5.0 | +7.1 |
| Spain media (OOD) | 19.5% | +51.7 | +44.5 | +4.5 |
| Belgium TV (OOD) | 11.1% | +65.3 | +51.5 | +13.5 |

**What this adds.** The authors' own implementation independently confirms — and
on the OOD targets *amplifies* — the covariate-shift failure: ReadMe is off by
**+44 to +60pp** on the out-of-support corpora. Two honest nuances:
- The official `readme0` is **biased even at baseline** (~+5 to +7pp) on this
  corpus, where our from-scratch version was near-zero. This is ReadMe's
  documented instability on short, sparse, multilingual text, compounded by the
  official estimator's profile-*intersection* step (it keeps only feature
  profiles present in both the labeled and target sets, discarding the rest and
  renormalizing) and its variance-weighted feature sampling. So the no-shift
  "validity check" is weaker for the official classic estimator than for ours.
- Magnitudes differ between the two implementations (intersection vs.
  union-with-zeros profile handling; variance-weighted vs. uniform feature
  selection; vocabulary size; number of bootstraps), but the **direction is
  unanimous across both implementations and all settings**: classic ReadMe does
  not transport under covariate shift, and the failure is largest exactly on the
  OOD genre shifts that are the paper's main stress test.

Outputs: `cap_analysis/data/readme0_official_results.csv`. Runner:
`/tmp/run_readme0.R` (reads the exported docs; uses a repo-local R library).

**Status of full ReadMe2 (`readme()`):** the TF estimator backend is installed

## Full ReadMe2 estimator — attempted, currently inconclusive

We installed the entire official stack (package + TensorFlow + torch/transformers +
multilingual BERT) and ran the **official `readme()` (ReadMe2) estimator** on
mBERT document embeddings of the identical CAP documents (28,900 unique docs
embedded; `rm2_embeddings.rds`). Result (bias pp):

| Scenario | True | ReadMe2 (mean-pooled mBERT) |
|---|---:|---:|
| Baseline | 7.9% | +19.7 |
| Country shift | 8.4% | +20.0 |
| Doc-type shift | 6.3% | +17.5 |
| Spain media (OOD) | 19.5% | +16.2 |
| Belgium TV (OOD) | 11.1% | +23.5 |

**This is not a usable test of ReadMe2, and we do not interpret it as one.** The
estimator is biased by ~+20pp *everywhere, including the no-shift baseline*. A
method that is +20pp off with no shift is mis-specified for the input it was
given — reporting it as "ReadMe2 fails under shift" would be wrong and unfair.

Diagnostics (reusing the cached embeddings; `readme()` at baseline) rule out the
obvious culprits — the +20pp baseline bias is unchanged by feature standardization
(+20.4) and by balancing the labeled set to the rare positive class (+20.3). The
cause is the **feature representation**: we fed mean-pooled mBERT vectors, whereas
ReadMe2's `undergrad()` constructs *quantile "vector summaries"* (per-embedding-
dimension 10th/50th/90th percentiles across a document's tokens). A faithful
ReadMe2 run needs those features (or the official `undergrad()` via the `text`
package's transformers backend), which requires re-embedding all ~29k documents at
the token level (~another hour of CPU) with uncertain payoff on this multilingual,
rare-class corpus.

**Bottom line:** the clean, defensible result is the **official classic ReadMe
(`readme0`)**, which fails under covariate shift (+44 to +60pp OOD), corroborating
our from-scratch implementation (which additionally has a near-zero baseline,
validating it). A fair ReadMe2 number is still open; see the recommendation.

## Caveats / honesty about ReadMe2

- The **+67.6pp country-shift catastrophe is partly an artifact of classic
  ReadMe's binary bag-of-words summary** and the extreme document-length gap
  (Belgian newspaper ≈ 1,900 chars vs. ≈ 80–150 elsewhere). ReadMe2's
  word-vector summaries are designed to be more robust to such surface features,
  so we should **not** present +67.6pp as representative of ReadMe2. A skeptical
  referee (one of whom may be an author of ReadMe) will make exactly this point.
- What ReadMe2 **cannot** fix is the underlying label-shift assumption. The OOD
  genre shifts (Spain media +4.5pp, Belgium TV +13.5pp) and the instability stem
  from `P(features|class)` genuinely differing across populations, which no
  better feature summary removes. So the *direction* of the result — ReadMe-family
  quantifiers don't transport under covariate shift — is robust; the *worst-case
  magnitude* is implementation-sensitive.
- **Recommended confirmation step:** run the official IQSS `readme` (ReadMe2) via
  `Rscript` (R is installed; the package + a multilingual embedding backend are
  not). If ReadMe2 tames the country-shift number but still shows material OOD
  bias and high variance, that is the strongest possible version of this section.
